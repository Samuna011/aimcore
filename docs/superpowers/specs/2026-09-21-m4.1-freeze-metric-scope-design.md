# M4.1 Freeze Addendum — Task Applicability (`metric_scope`)

**Date:** 2026-09-21  
**Status:** Implemented (freeze gate complete)  
**Parent:** [2026-09-20-m4.1-sense-analysis-design.md](./2026-09-20-m4.1-sense-analysis-design.md)

**Depends on:** TRACKING v2 (`0.12.2`) rapid-fire shots  

## Goal

Lock M4.1 as the frozen deterministic metrics layer before M4.2 condition comparison. Add **task applicability metadata** so consumers know which metrics are primary vs secondary vs partial per trial type — especially TRACKING, where click-associated acquisition metrics are not the primary performance signal.

## Frozen (do not change under `"1"`)

| Item | Value / rule |
|------|----------------|
| Segmentation | Hybrid C |
| Onset | 40 °/s |
| Settle | 15 °/s for 80 ms |

| BehaviorMetrics | as shipped |

| Quality flags | as shipped |
| `analysis_version` | `"1"` |

Silent retunes require a new `analysis_version`.

## Additive: `metric_scope`

Every `AnalysisResult` includes:

```json
"metric_scope": {
  "shot_accuracy": "applicable",
  "acquisition_metrics": "applicable",
  "continuous_tracking_metrics": "not_applicable",
  "click_association": "applicable"
}
```

### Enum

`applicable` | `secondary_reference` | `partial` | `not_applicable`

### Per trial type

| Key | STATIC_CLICK / GRIDSHOT | TRACKING |
|-----|-------------------------|----------|
| `shot_accuracy` | applicable | applicable (**primary** = hits / shots) |
| `acquisition_metrics` | applicable | secondary_reference |
| `continuous_tracking_metrics` | not_applicable | secondary_reference (on-target time / ratio from trial record) |
| `click_association` | applicable | partial |

### TRACKING interpretation

- **Primary performance:** 20 Hz shot accuracy (`hits / shots` on the trial record).
- **Secondary:** on-target hold time (`score_secs`) and on-target ratio (`score_secs / duration_secs`).
- **Not primary:** click-associated acquisition / Hybrid C behavior metrics — still computed when a movement links a shot, but scoped so M4.2+ does not treat them as the task score.

Derivation is a pure function of `trial_type` (and existing analyze gates). No new telemetry columns.

## Task gate (clarification)

- `STATIC_CLICK`, `GRIDSHOT`: always analyzable when camera samples exist.
- `TRACKING`: analyzable when `aim_shots` non-empty (task_version 2+); empty shots → `InsufficientTelemetry`.
- Unknown types → `UnsupportedTrialType`.

Parent doc “TRACKING unsupported” is superseded by this addendum + TRACKING v2.

## Non-goals

- TRACKING-specific re-segmentation / tracking_error / regime bins
- Changing any frozen constant or formula
- Lab UI, recommendations, DB writes of analysis
- Bumping `analysis_version`
