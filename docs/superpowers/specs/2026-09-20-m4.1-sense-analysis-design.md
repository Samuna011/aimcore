# M4.1 — Sensitivity & Acceleration Analysis Engine (Deterministic Layer)

**Date:** 2026-09-20  
**Status:** Approved for implementation (brainstorm locks)  
**Depends on:** M3.y five-layer aim telemetry, Aim History load paths, LCG full-unit fix (`0.12.1`)  
**analysis_version:** `"1"`  
**App experiment_version:** unchanged (offline crate; no Lab UI / no setting changes)  
**Scope:** New `sense-analysis` crate — reconstruct → segment → BehaviorMetrics + ExposureMetrics + quality; ephemeral JSON dump

## Goal

Build a **deterministic analysis engine** that turns a completed click-task trial into reproducible movement segments and metrics, using **only** persisted telemetry and the trial’s frozen configuration/versions.

Core question deferred to M4.2+: *which parameter causally explains a behavior change?*  
M4.1 answers only: *what happened in the input → processor → camera → target chain, segmented and measured?*

## Non-goals

- Parameter attribution / “cause” fields
- Sensitivity or acceleration recommendations
- ML / personalization
- Lab UI, automatic setting changes, good/bad classifications
- TRACKING segmentation or tracking_error / reaction_time / regime bins
- Public CLI
- Writing `aim_trials.metrics_json` or any analysis side table
- Silent retuning of `analysis_version` `"1"` constants or formulas

## Pipeline

```text
SQLite DB
   │
   ▼
telemetry loader  →  AnalysisBundle
   │                   trial + inputs + camera + shots + target events
   ▼                   (no live settings)
reconstruct       →  time-aligned series
   │                   camera angular speed (°/s)
   │                   raw/processed speeds, acceleration_scale
   ▼
segment           →  candidates → shot links → primary + correction + flags
   ▼
behavior + exposure  (separate namespaces; never “cause”)
   ▼
quality           →  first-class flags (non-destructive)
   ▼
AnalysisResult    →  JSON dump
```

**API sketch:** `analyze_trial(bundle, AnalysisConfig::v1()) -> Result<AnalysisResult, AnalysisError>`

**Invariant:** The analysis result must be reproducible entirely from the persisted trial data and its recorded configuration/version. No current settings, live processor, current task RNG, or game state may be consulted.

**Loader:** Analysis requires the **full five-layer** bundle including `aim_input_samples`. If History’s existing load omits inputs, extend the telemetry load API (or add an analysis-specific load) so reconstruction does not depend on the app runtime.

**Task gate:** `STATIC_CLICK` and `GRIDSHOT` only. `TRACKING` (and unknown types) → `AnalysisError::UnsupportedTrialType`.

## Segmentation contract (`analysis_version` `"1"`)

### Frozen config

| Knob | Value |
|------|--------|
| `primary_signal` | `camera_angular_speed_deg_per_s` |
| `onset_deg_per_s` | `40.0` |
| `settle_deg_per_s` | `15.0` |
| `settle_ms` | `80` |
| `min_movement_ms` | `40` |
| `shot_attach_ms` | `150` |
| `post_click_max_ms` | `300` |
| `gap_ms` | `50` |
| `jitter_window_ms` | `40` |
| `scale_mismatch_eps` | `1e-3` (absolute on `acceleration_scale`) |

**Invariant:** `0 < settle_deg_per_s < onset_deg_per_s`.

Retuning any of these (or changing metric definitions) requires bumping `analysis_version`. Never silently change `"1"` after data collection.

### Candidate detection

1. **Start** when reconstructed camera angular speed `>= onset_deg_per_s`.
2. **Settle clock** starts when speed `< settle_deg_per_s`; resets if speed returns to `>= settle_deg_per_s` before `settle_ms` completes.
3. **End** at the first timestamp where speed has remained `< settle` continuously for `>= settle_ms`.
4. Candidates with duration `< min_movement_ms` are **rejected as candidates** (not erased from telemetry).

Raw/processed input activity is **supporting evidence** for quality (e.g. mismatch), not the primary gate.

### Shot association

Hit/miss must **not** influence segment boundaries (no outcome leakage).

For every `aim_shots` row:

1. Prefer a candidate whose active interval **contains** the click timestamp.
2. Else attach the nearest **preceding** candidate if `click_ns - candidate_end_ns <= shot_attach_ms`.
3. Outcomes:
   - exactly one eligible → `primary_movement_id`
   - zero → `ORPHAN_SHOT`
   - multiple equally/ambiguously eligible → `AMBIGUOUS_SHOT`

**Never** invent a movement solely because a click occurred. Velocity candidates may be rejected by quality/duration rules even if shots exist.

### Multi-shot movement

If one candidate contains multiple shots, **do not auto-split**. Keep the kinematic interval and flag `MULTI_SHOT_MOVEMENT`. Each shot may still associate to that interval as its primary movement.

### Post-click correction

Separate from the primary movement:

```text
primary movement → click → optional post-click correction window
```

Window ends at the earliest of:

- velocity settling (same settle rule), or
- next movement onset, or
- `post_click_max_ms` after click

### Quality flags (first-class, non-destructive)

| Flag | Meaning |
|------|---------|
| `ORPHAN_SHOT` | no eligible primary candidate |
| `AMBIGUOUS_SHOT` | multiple eligible candidates |
| `MULTI_SHOT_MOVEMENT` | candidate spans >1 shot |
| `NO_SETTLE` | candidate never met settle criteria before trial end / unrecoverable gap |
| `INSUFFICIENT_TELEMETRY` | missing/too-sparse samples for required metric |
| `TIMESTAMP_GAP` | adjacent camera (or input) sample `dt > gap_ms` where **`gap_ms = 50`** frozen in v1 config |
| `CAMERA_INPUT_MISMATCH` | stored `acceleration_scale` disagrees with recomputed Linear expectation beyond ε (`ε = 1e-3` relative or absolute — freeze one rule in implementation; default absolute `1e-3` on scale) |

`PREMATURE_SETTLE` is **not** emitted in analysis_version `"1"` (deferred until a precise definition exists).

Flags do **not** delete segments. Metrics that do not depend on an unambiguous shot boundary may still be emitted.

## Metrics

Two namespaces only. M4.1 **must not** emit cause/recommendation fields.

### Geometry

- Units: **degrees** (angular). No screen-normalized primary metrics in v1.
- Look at click from shot yaw/pitch; target from camera origin → target center (shot pose).
- **Approach axis:** great-circle from look-at-movement-start → look-at-target (fallback + quality if start pose missing).
- Sign: **positive = past target** along approach.

### BehaviorMetrics (primary movement)

| Metric | Definition |
|--------|------------|
| `endpoint_error` | Signed angular miss at click along approach |
| `overshoot` | Max signed past-target excursion along approach during primary **before** click; else `0` |
| `movement_duration` | `end_ns - start_ns` |
| `path_length` | Σ angular steps of camera path in primary |
| `path_efficiency` | angular chord(start→click) / `path_length` (undefined/omit if path ≈ 0) |
| `angular_velocity` | mean + peak camera °/s in primary |
| `angular_acceleration` | peak \|d(°/s)/dt\| in primary |
| `jitter` | RMS of high-pass residual of angular speed; local-mean window **40 ms** frozen for v1 |

Omit primary BehaviorMetrics for a shot when association quality blocks them (e.g. `ORPHAN_SHOT`). Hit/miss is a **label**, not an input to magnitudes.

### BehaviorMetrics (post-click correction)

If correction window non-empty:

| Metric | Definition |
|--------|------------|
| `correction_magnitude` | Angular **path length** in the correction window (canonical for v1) |
| `correction_duration` | Window length |

### ExposureMetrics (primary interval)

Derived from **stored** samples (`raw_*`, `processed_*`, `acceleration_scale`, `dt_used_ns`):

| Metric | Definition |
|--------|------------|
| `raw_speed` | mean + peak |
| `processed_speed` | mean + peak |
| `acceleration_scale` | mean + peak of stored scale |
| `gain_ratio` | mean + peak of ‖processed‖ / ‖raw‖ (`1.0` if raw ≈ 0) |
| `cap_exposure` | Fraction of samples where stored scale is at configured Linear cap (ε-match). Processor `none` → `0` with N/A note |
| `processor_time` | Σ `dt_used_ns` in interval |

**Quality-only recompute:** expected Linear scale from raw + frozen `processor_config_json`; disagreement beyond ε → `CAMERA_INPUT_MISMATCH`. Does **not** rewrite ExposureMetrics.

### Deferred (not v1)

`tracking_error`, `reaction_time`, movement regime labels (micro/short/…), screen-normalized dual metrics, attribution, condition comparison.

## Output

`AnalysisResult` (ephemeral):

- `analysis_version`
- Trial identity + frozen experiment/task/processor/version fields from the row
- Candidates (summary sufficient for debug; full intervals allowed)
- Per-shot: primary link, correction window, BehaviorMetrics, ExposureMetrics, quality flags

JSON dump: stable names; deterministic ordering (`shot_index` / `movement_id` ascending).

**Hard errors:** unsupported trial type, loader failure, empty required streams when analysis cannot start.  
**Soft issues:** quality flags; keep usable partial metrics.

**Persistence:** none in M4.1 (no DB write).

## Tests

- Hysteresis onset/settle; settle-clock reset
- Min-duration candidate reject
- Orphan / ambiguous / multi-shot association
- Post-click trim by settle / next onset / max window
- Endpoint sign + overshoot = 0 when never past target
- Cap exposure capped vs uncapped fixtures; `none` processor
- Scale mismatch → quality flag without mutating exposure
- TRACKING → unsupported
- Golden JSON for one canned STATIC_CLICK-like fixture under `analysis_version` `"1"`
